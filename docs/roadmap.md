# План развития (roadmap)

Задачи в порядке приоритета. Актуально на ноябрь 2026.

## Приоритет 1 — Переход на актуальную версию Astro

**Статус: выполнено (ноябрь 2026).** Проект переведён с `astro 5.18.2` на **7.4.13**,
TypeScript обновлён до 5.9.3. Сборка, `npx tsc --noEmit` и визуальная проверка всех
страниц через `npm run preview` — без ошибок. Попутно исправлена скрытая ошибка типов в
`src/scripts/viewer.ts` (сужение `null` не сохранялось в hoisted-функциях `render` /
`updateControls`). Breaking changes v6/v7 проект не затронули: Rust-компилятор принял
разметку, потери пробелов при новом `compressHTML: 'jsx'` не обнаружено, требование
Node.js (>= 22.12) зафиксировано в документации.

Установлен `astro 5.18.2`, актуальная версия — **7.4.13**. Линейка 5.x больше не

На что обратить внимание:

- **Node.js >= 22.12** (требование Astro 6+; в `AGENTS.md`/`README.md` сейчас указано
  `>= 22` — уточнить).
- **v6**: Vite 7 (своих Vite-плагинов нет — не затрагивает); `getStaticPaths` — params
  только строки (у нас уже строки).
- **v7**: Vite 8; новый Rust-компилятор строже относится к невалидному HTML — прогнать
  `npm run build` и проверить ошибки (текущая разметка валидна).
- **v7**: `compressHTML` по умолчанию изменён на `'jsx'` — возможны пропавшие пробелы
  между инлайн-элементами. Визуально проверить шапку/футер/страницы через
  `npm run preview`; при расхождениях либо поправить разметку, либо вернуть
  `compressHTML: true` в `astro.config.mjs`.

Шаги:

1. `npx @astrojs/upgrade` (или вручную поднять `astro` до `^7`).
2. `npm run build` без ошибок.
3. `npm run preview` — визуальная проверка всех трёх страниц и просмотрщика.
4. Обновить упоминания версии в `README.md` и `AGENTS.md` («Astro 5» → актуальная,
   Node >= 22.12).

## Приоритет 3 — Замечания по просмотрщику

**Статус: выполнено (ноябрь 2026).** Реализовано вместе с новыми возможностями тулбара:

- Ошибки рендера страниц (`getPage` / `page.render`) обрабатываются try/catch —
  сообщение выводится в `data-role="status"` (у него `role="status"`, т.е. это
  aria-live-регион), область просмотра скрывается до успешного рендера.
- Навигация с клавиатуры: `←`/`→` — страницы, `+`/`-` — масштаб; обработчик
  игнорирует фокус в полях ввода (включая инпут номера страницы). Фокус-стили
  (`:focus-visible`) у кнопок и инпута.
- Canvas получил `role="img"` и динамический `aria-label`
  («Название — страница N из M», обновляется при листании).
- Ввод номера страницы: `<input type="number">` с валидацией и clamp в
  `[1, numPages]` (Enter — переход и снятие фокуса, `change` — на blur).
- Кнопки «по ширине» и «по высоте»: масштаб вычисляется из
  `page.getViewport({ scale: 1 })` и внутренних размеров `.viewer__canvas-wrap`
  (`scrollbar-gutter: stable` резервирует место под скроллбар).
- Кнопка «во весь экран» на Fullscreen API (`container.requestFullscreen()`),
  состояние — через `aria-pressed` по событию `fullscreenchange`.

<details>
<summary>Исходное описание задачи (архив)</summary>

### viewer.ts: обработка ошибок и доступность (a11y)

- Сейчас обрабатывается только ошибка **загрузки документа** (`getDocument`). Ошибки
  рендера отдельных страниц (`getPage` / `page.render`) не ловятся — обернуть в
  try/catch с выводом сообщения в `data-role="status"`.
- Нет навигации с клавиатуры: добавить стрелки ←/→ для страниц, `+`/`-` для зума,
  видимые фокус-стили у кнопок тулбара.
- Нет текстовой альтернативы для `<canvas>`: добавить `role="img"` с `aria-label`
  (название документа + номер страницы) и/или `aria-live`-регион, озвучивающий смену
  страницы.

</details>

### Размер бандла

PDF.js загружается целиком на странице просмотра: ~335 КБ JS (gzip ~99 КБ) + воркер
~1,37 МБ. Для вьюера это приемлемо, но возможна lazy-загрузка: динамический
`import()` модуля просмотрщика при попадании контейнера в viewport или по первому
взаимодействию. Оценить целесообразность после миграции на новую версию Astro.

## Приоритет 4 — Переключатель темы (светлая/тёмная)

С сохранением выбора в `localStorage`. Концепция согласована:

- Перевести дизайн-токены со SCSS-переменных (`$color-*`, compile-time) на CSS custom
  properties: значения в `:root`, переопределения в `[data-theme='dark']`; в блоках —
  `var(--color-*)`. Структура `main.scss` и БЭМ сохраняются.
- Кнопка в шапке (`header__inner`), иконки солнце/луна inline-SVG; обработчик — по
  конвенции через `initTheme(container)` в `src/scripts/theme.ts`, `aria-label` и
  фокус-стили сразу (увязать с приоритетом 3).
- Против вспышки светлой темы (FOUC): маленький инлайн-скрипт (`is:inline`) в `<head>`
  `BaseLayout.astro`, выставляющий `data-theme` на `<html>` до первой отрисовки —
  осознанное исключение из конвенции «данные через `data-*`» (модульные скрипты Astro
  грузятся с `defer` и выполняются поздно).
- При отсутствии записи в `localStorage` — системная тема (`prefers-color-scheme`),
  опционально подписка на её смену.
- Добавить `color-scheme: light/dark` для нативных контролов и скроллбаров.
- Canvas с PDF не инвертировать (документ остаётся белым); проверить контраст
  `button--primary` и тень `viewer__canvas` в тёмной теме.

## Приоритет 5 — Колонка миниатюр страниц

Левая колонка с превью страниц, клик по миниатюре — переход (как в референсе
library.contentednet.com). Оценка: ~0,5–1 день.

- Разметка: `.viewer__container` становится flex-строкой — колонка `.viewer__thumbs`
  (~120px, `overflow-y: auto`) + текущая область просмотра; на узких экранах колонку
  скрывать/сворачивать.
- Рендер миниатюр на scale ~0,15 (дёшево по памяти), обязательно lazy через
  IntersectionObserver — иначе длинный документ будет рендериться целиком при открытии.
- Клик → `goTo(n)` (постраничный режим) / `scrollIntoView` (лента, приоритет 6).
- Подсветка активной миниатюры и её прокрутка в видимую область при навигации.
- Совместимо с обоими режимами отображения; делать перед лентой.

## Приоритет 6 — Режим «лента» (continuous scroll)

Отображение всех страниц подряд с общей прокруткой вместо постраничного режима.
Оценка: ~1–2 дня, переработка ядра `viewer.ts`.

- Стек canvas'ей (по одному на страницу) в общей прокручиваемой колонке.
- Оконный рендер: видимые страницы ±1–2 через IntersectionObserver; дальние canvas'ы
  при большом масштабе очищать (иначе scale 3 на длинном документе съест память).
- Отмена рендеров через `RenderTask.cancel()` при быстрой прокрутке/зуме (текущих
  флагов `pendingRender` недостаточно).
- «Текущая страница» вычисляется из позиции скролла; инпут/стрелки/миниатюры —
  `scrollTo` к нужной странице.
- «По ширине» работает естественно; «по высоте» в ленте теряет смысл.
- Альтернатива: компоненты `pdfjs-dist/web/pdf_viewer.mjs` (`PDFViewer` +
  `PDFThumbnailViewer`) — лента и миниатюры почти из коробки, но с чужой DOM-структурой
  и стилями; не выбирать, пока собственный код справляется.

## Дальнейшее развитие (по требованию заказчика)

Из исходного ТЗ не реализована только админка. Статистика просмотров и скачиваний
сделана через Яндекс Метрику (без бэкенда): сниппет в `BaseLayout.astro`, цели
`pdf_view` (после первой успешной отрисовки страницы) и `pdf_download` (клик по
кнопке «Скачать») с параметром `document_id` — включается заданием
`siteConfig.yandexMetrikaId` в `src/config.ts` (0 — выключено). Цели нужно создать
в интерфейсе Метрики (тип «JavaScript-событие»).

При необходимости самостоятельной загрузки файлов клиентом — отдельный бэкенд
(например, PocketBase + S3) с сохранением текущей статической публичной части.
