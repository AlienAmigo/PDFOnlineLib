# Добавление PDF-документа

Документы добавляются вручную, без админки: файл кладётся в репозиторий, а запись о нём —
в каталог. После пересборки у документа появляется страница просмотра по адресу
`/view/<id>`.

## Шаги

### 1. Положить файл

Скопируйте PDF в `public/pdf/`:

```bash
cp ~/Downloads/dogovor.pdf public/pdf/
```

Имя файла — латиница, цифры, дефис; без пробелов и кириллицы (иначе возможны проблемы
с URL на некоторых хостингах).

### 2. Добавить запись в каталог

Откройте `src/data/pdfs.ts` и добавьте объект в массив `entries`:

```ts
const entries: PdfEntry[] = [
  // ...
  {
    id: 'dogovor', // slug страницы: /view/dogovor
    title: 'Договор аренды', // заголовок на странице просмотра
    description: 'Типовая форма', // описание под заголовком (можно пустую строку)
    fileName: 'dogovor.pdf', // имя файла в public/pdf/
  },
];
```

Требования к полям:

- `id` — уникальный slug из латиницы, цифр и дефисов; именно он попадает в URL.
- `fileName` — должен точно совпадать с именем файла в `public/pdf/`.
- `title` и `description` — произвольный текст, отображается над просмотрщиком.

### 3. Пересобрать и опубликовать

```bash
npm run build
```

Содержимое `dist/` — на хостинг (см. [Деплой](deployment.md)).

## Проверка

После сборки страница доступна локально:

```bash
npm run preview   # затем открыть http://localhost:4321/view/dogovor
```

Проверьте: документ загружается, работает переключение страниц и кнопка «Скачать».

## Частые ошибки

| Симптом                           | Причина                                       |
| --------------------------------- | --------------------------------------------- |
| `/view/<id>` отдаёт 404           | нет записи в `entries` или не пересобран сайт |
| «Не удалось загрузить документ»   | `fileName` не совпадает с именем файла        |
| 404 на сам файл `/pdf/<fileName>` | файл лежит не в `public/pdf/`                 |
